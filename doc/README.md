# 📁 项目文档中心（doc/）

本目录用于记录 Cyber AI Festival 平台的**待解决问题清单**与**工作追踪**，方便前后端协同推进。

> 关联仓库：`cyber_ai_festival`（前端）/ `cyber_ai_festival_be`（后端）

## 目录结构

| 文件 | 用途 |
|------|------|
| `README.md` | 本说明：框架、状态/优先级定义、更新规范 |
| `ISSUES.md` | 问题清单主文件：汇总表 + 每个问题的详情 |

## 状态定义（Status）

| 状态 | 含义 | 规则 |
|------|------|------|
| `open` | 未开始 | 已确认存在的问题，尚未动手 |
| `in-progress` | 进行中 | 正在处理，需在详情里写明当前进展 |
| `done` | 已完成 | 已修复并验证，记录完成日期与改动位置 |
| `blocked` | 阻塞中 | 遇到依赖/决策阻塞，写明阻塞原因 |
| `wontfix` | 不处理 | 有意为之或放弃，写明原因 |

## 优先级定义（Priority）

| 优先级 | 含义 | 处理要求 |
|--------|------|----------|
| `P0` | 必须尽快处理 | 安全漏洞 / 数据链路断点，上线前必须解决 |
| `P1` | 强烈建议 | 明显影响体验或健壮性的问题，应尽快排期 |
| `P2` | 体验完善 | 锦上添花，有空再处理 |

## 分类定义（Category）

| 分类 | 前缀 | 覆盖范围 |
|------|------|----------|
| 安全 | `SEC-` | 鉴权、密钥、数据可信、接口滥用 |
| 架构工程 | `ARCH-` | 前端工程结构、数据链路、复用性 |
| 后端工程 | `BE-` | FastAPI 后端实现、迁移、运维 |
| 各游戏 | `G1-`~`G5-` | 单个游戏内的具体问题 |

## 更新规范（Checklist）

每次处理问题或会话结束时，**必须同步更新本清单**：

- [ ] 开始处理某问题 → 状态改为 `in-progress`，注明开始日期
- [ ] 完成某问题 → 状态改为 `done`，注明完成日期与改动文件/提交
- [ ] 发现新问题 → 追加到 `ISSUES.md`，分配新 ID、分类、优先级
- [ ] 放弃某问题 → 状态改为 `wontfix` 并写明原因
- [ ] 变更 ID 前先检查是否存在被引用，避免断链
